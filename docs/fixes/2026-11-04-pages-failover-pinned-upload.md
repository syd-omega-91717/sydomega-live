### Pages failover build: replace the composite action that nests an unpinned action (2026-11-04)

**Why.** The `build` job in `.github/workflows/omega-static-failover.yml` failed on every push to `main` from at least #1148 to #1157. Run 41736517574, step `Set up job`: `The action actions/upload-artifact@v4 is not allowed in syd-omega-91717/sydomega-live because all actions must be pinned to a full-length commit SHA.` The workflow pinned `actions/upload-pages-artifact` to a SHA, but that is a composite action whose `action.yml` (read at commit 56afc609) calls `actions/upload-artifact@v4` by tag, and the policy rejects the nested tag. No workflow in the repo names `upload-artifact@v4`, which is why a grep found nothing.

**Fix.** The one composite step is replaced by its own two steps: `Archive Pages artifact` (the Linux `tar` branch of upload-pages-artifact v3.0.1, verbatim: `--dereference --hard-dereference --directory public -cvf $RUNNER_TEMP/artifact.tar --exclude=.git --exclude=.github .`) and `Upload Pages artifact` using `actions/upload-artifact@ea165f8d65b6e75b540449e92b4886f43607fa02` (v4.6.2, the SHA other workflows here already use; package.json at that commit reads 4.6.2) with `name: github-pages`, `retention-days: 1`, `if-no-files-found: error`, the same inputs the composite passed. The artifact name, tar layout and retention are unchanged, so `deploy-pages` reads it as before. Nothing else in the workflow changed.

**Verified.** The archive step's exact script, run under `sh` on a synthetic folder containing `.git`, `.github`, a symlink, a hard link and `CNAME`: exit 0, entries `./ ./CNAME ./assets/ ./assets/a.css ./assets/b.css ./index.html ./link.html`, zero `.git`/`.github` entries, symlink followed. `workflow-contract.py`, `workflow-contract-lint.py` and the full `scripts/contract-suite.py` pass; `scripts/tests` OK; idea ledger and skill registry regenerated and checked.
