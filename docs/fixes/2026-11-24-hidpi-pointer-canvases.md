### hi-DPI wave 3: the pointer-driven canvases, and three bugs in the helper that only they exposed (2026-11-24)

**Why.** The owner asked for the pointer-driven canvases next. They are the risky group: a backing store larger than the CSS box silently breaks any handler that maps a pointer through `canvas.width / rect.width`, or that detects a resize by comparing `offsetWidth` with `canvas.width`. Pixels cannot show that, so the work added a pointer harness before it trusted the change.

**Done: 10 pages, 12 canvases.** `agent-network`, `architect`, `atlas` (8 reads of `canvas.width/height` moved to `cw()`/`ch()`), `dashboard` (galaxy, personal wheel, and its resize detector), `ecosystem` (resize detector), `knowledge`, `network` (pointer scaling now uses `OmegaCanvas.size`), `nexus`, `mindmap`, `queue`. No remaining `canvas.width / rect.width` or `offsetWidth !== cv.width` anywhere in `*.html` (pinned by `test_no_page_scales_a_pointer_position_by_the_backing_store` and its sibling).

**Three helper bugs, found by running these pages, all fixed in `omega-canvas-hidpi.js`.**
1. *Zero clamped to 1.* A canvas measured while hidden has CSS width 0. The original stored `0 x H`, which has no aspect ratio, so the box fell back to a default; `Math.max(1, ...)` stored `1 x H`, a 1:H ratio that laid `dashboard`'s galaxy out **295,920 px tall** (width x H), which the page then read back into the next store. The merged pages all pass a non-zero fallback width, so production was not affected; this wave passes raw zeros and would have shipped it. Zero now stays zero, and the other axis is not scaled by the ratio either (a `height:auto` canvas adopts its store's intrinsic height, which made the box 3x too tall).
2. *Height pinned from a layout side effect.* Detecting "the box height changed after the store changed" is fooled by percentage heights in containers with no definite height: `agent-network` was pinned to `height:auto` at 481 px against 1,339 at 1x. The helper now never detects or pins a height (only `{size:true}` sets one), and pins only the width, so a `max-width:100%` rule shrinks the canvas uniformly as before.
3. *A pin was forgotten.* Once a canvas is pinned, a later `fit()` with a new size saw an unchanged box and left the old CSS size (`mindmap` on window resize). A pinned canvas stays pinned.

**Verified.** `scripts/verify-hidpi-pointer.js` (new): scans a 12 px grid of pointer positions over each canvas, dispatched inside the page against the page's own handlers (a cursor change, a tooltip, a panel, a selected node), plus one real mouse hit and one real miss per scale; compares the nodes hit at 1x, 2.625x (a real phone ratio) and 3x as clusters in box-relative coordinates. **80/80** on 9 pages. Non-vacuous by construction (needs at least 4 hit cells at 1x and a repeat-at-1x noise floor). Mutations caught: pointer scaled by the backing store again, network: hit cells 51 at 1x against 2 at 3x, cluster match 0.00; zero clamped to 1 again: dashboard box 776,700 px tall. `scripts/verify-hidpi-charts.js` now covers 38 charts including these pages' layout, resolution and growth: **205/205**. Full unit suite 2,194 tests OK (2 skipped: the opt-in browser suites); contract suite 95 gates, 0 failing; `audit.py` 0 critical / 8 warnings; XSS and CSP ratchets pass. **Not caught by any browser test:** the pinned-height squash (mutation 2), because the harnesses freeze `agent-network`'s height to work around its own growth; it is pinned by `test_the_helper_never_pins_a_height_unless_asked`, which fails on that mutation.

**Pre-existing defects found and NOT fixed** (all in `GAP_ANALYSIS.md` §S): `agent-network`'s canvas grows without bound on `origin/main`; five canvases (`architect`, `knowledge`, `mindmap`, `queue` topology, `atlas`) size themselves before their layout settles and are shown scaled; `atlas` stacks all its nodes on one point in headless Chromium; one page's content column intermittently renders 868 px wide instead of 539 (1 load in 30).

**Not done / not verified.** (1) `atlas.html`'s pointer hit-testing is **not** browser-verified: its nodes collapse onto one point in headless Chromium, so there was nothing to hit; it is the same `cw()`/`ch()` substitution checked on the other pages. (2) The two browser suites are slow (about 12 and 8 minutes) and layout-timing sensitive, so they run only with `OMEGA_HIDPI_BROWSER=1`; the static contracts always run. They needed up to three attempts per chart to absorb the 868/539 flip. (3) Software Chromium only; no real touch device (the touch handlers in `architect` and `knowledge` were not exercised). (4) About 48 canvas files remain, none pointer-driven; see the PR. (5) Not deployed.
