### Character roster: the 12 characters and the member's progress on each (no new table) (2026-11-15)

**Why.** The idea is "every member has a main character and can collect other evolving characters". Reading `0004_omega_nested_matrix.sql` showed the platform already stores exactly that shape: `matrix_progress` is one row per member per sign (12 tracks, own axes `a,b,c` and `phase`), `my_matrix()` returns it. `matrix.html` shows it as an anonymous grid; nothing presented the 12 as characters or tied them to the member's main character. The plan merged the same day (`docs/plans/CHARACTER_LAB_PLAN.md`, #1294) proposed a new `member_characters` table and an unlock rule based on "the axis tied to the character's element": both wrong (the table duplicates `matrix_progress`; the canon's axes are Knowledge/Mastery/Contribution, not elements). The plan now carries a revision note saying so.

**Fix.** `omega-character-card.js` gains `renderRoster` and a `[data-omega-character-roster]` mount, injected by `bg.js` where a mount exists. 12 tiles from `OmegaCanon.tracks` (sign, god, agent), the member's main sign marked from `profiles.sign`, progress from `rpc('my_matrix')` phase-1 rows (the rows `matrix.html` uses). A sign whose axes are all 1 reads "Not started"; no row reads "No progress data"; an RPC error shows "Roster unavailable" (checked, not assumed). Mounted at the top of the MATRIX tab of `character.html`. No schema change, no flag, no write from the module (`my_matrix()` itself seeds the caller's own missing rows, as it already does on every page that calls it). Tile modifiers are `is-started`/`is-mine`: a first draft used the class `main`, which is the platform's content column, and `omega-legal.js` appended the site footer into the Aries tile (seen in a screenshot, not in the DOM check). The test now bans `main`/`on`/`lf`/`card`/`side`/`shell` tokens. The plan revision and a new `GAP_ANALYSIS.md` §S item record the `advance_matrix` finding (below).

**Verified.** Headless Chromium, `character.html`, MATRIX tab. Stub with no progress data: 12 tiles, Aries marked, "No progress data", 0 errors. Stub patched to return `my_matrix`-shaped rows (copy of the harness in the scratchpad, not committed): Aries `(5,3,1) · 33.3%`, Leo `(2,1,1) · 10%`, the other 10 "Not started", phase-2 rows ignored, 2 tiles started, 0 errors. Direct renders: all-ones seeded, no rows, a hostile `<img onerror>` value (renders a dash, no `img`/`script` created), no main sign. Footer after the class fix is a child of the page shell again (`[DIV.omega-legal-footer, DIV#app]`). Phone 390x844: no horizontal overflow, 2 columns, 0 errors. `test_character_card.py` 10 tests.
