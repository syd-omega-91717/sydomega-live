### Hub module pickers were blocked iframes; now links (2026-11-05)

**Why.** Each of the 15 hub pages listed its specialist pages as chips that opened an `<iframe>` dialog (`omega-single-page-workspaces.js`). `vercel.json` sends `X-Frame-Options: DENY` and `frame-ancestors 'none'` on `/(.*)` (the repo's `security-headers-contract.py` requires both), so the browser refuses every frame. Reproduced in headless Chromium: the same chip loads `contracts.html` with no headers and is blocked with `Framing 'http://localhost:8765/' violates ... "frame-ancestors 'none'"` with the exact production header set applied. `verify-runtime.js` cannot see it: its server sends no production headers. A permitted frame would also load a second full platform (`bg.js` + ~160 modules) inside the first.

**Fix.** Chips are now `<a href="/<page>.html">` links; the dialog and iframe are gone; an old `#module=<key>` deep link redirects to the page. Every URL is unchanged and no security header was loosened. The Services hub gains `studio`, `creation-studio`, `project-studio`, `creator`; the Govern hub gains `lab`, `design-system`, `design-showcase`, `design-lab` (all already belonged to those sections in `nav.js`). `config/omega-single-page-workspaces.json` is updated and a test pins it equal to the loaded list.

**Verified.** In headless Chromium with the `vercel.json` header set applied to every page: 6 hubs (services, govern, invest, vault, achieve, archive) show 0 dialogs, 0 frame errors, the expected chip counts (12, 19, 8, 8, 17, 3), each chip click lands on the real page with content, and `<hub>.html#module=<key>` redirects. New `scripts/tests/test_hub_picker_links.py` (5 tests).

**Not done / not verified.** The live site's headers could not be read from this environment (egress proxy 403), so that production sends `DENY` is inferred from `vercel.json` plus the repo's production probe listing the header as required, not observed. `compliance`, `monitoring-dashboard`, `data-observatory` stay standalone (they belong to other sections); the Owner Deck stays out of member hubs.
