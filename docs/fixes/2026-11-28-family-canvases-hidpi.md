### family.html constellation and tree: 1:1 stores, one loop, tree painted its whole store (2026-11-28)

**Why.** Measured with an owner stub seeding 3 `family_nodes` and 2 `bloodline_nodes` (scratchpad probe, now `scripts/verify-family-canvases.js`), against a worktree of `main`:
- Constellation `#con-cv`: store 1840x520 for a 884x260 box at 1000px (x stretched 2.08, y 2.0), 748x520 for 338x260 at 390px (x stretched 2.21), and still 2x on a dpr-3 phone. It read `offsetWidth` once, so the approval guard (CLAUDE.md 8.1 class 3) or a resize left it stale. Every `drawConstellation` call (boot() re-runs after each add/remove) started another `requestAnimationFrame` loop on top of the last one, never cancelled.
- Tree `#tree-canvas`: stored `W*2` x 600 and drew a 300-unit scene under `scale(2,1)`, so only the top half of the store held pixels, x was stretched 2x, and it never refitted. It had no CSS size of its own. It also re-rolled its star field with `Math.random()` on every draw.

**Fix.** `family.html` only. Both canvases fit through `OmegaCanvas.fit(cv, W, H, {scale: max(2, ratio())})`, so the store is box x density (never below the old 2x floor, 3x on a dpr-3 phone). W is measured from the box; a `ResizeObserver` refits and re-lays out nodes, ignoring width 0 (a hidden tab would otherwise refit to the 800px fallback). The constellation cancels its previous loop before starting one. CSS height is set inline from JS (260/300): bg.js's `canvas{height:auto}` is a later sheet and beats a page rule, and the first attempt at a page rule left the box 220px tall at 390px. Tree stars use a fixed golden-ratio sequence, so a refit does not re-roll the sky. The scene is drawn in CSS pixels throughout (no `scale(2,1)`).

**Verified.** `node scripts/verify-family-canvases.js`: PASSED 24 of 24 (store = box x max(2, dpr) on both axes, 260/300px boxes, painted from 0-5% to 95-100% of the store, constellation refit after a bloodline-tab round trip, no page errors) at 1000@1, 1000@3 and 390@3. The same script against the `main` worktree: 16 failures, so the check does detect the old behaviour. `python3 -m unittest scripts.tests.test_hidpi_charts`: 37 tests OK; the browser case runs with `OMEGA_HIDPI_BROWSER=1` and passed. The static test replaces the old pinned "family constellation left alone" assertion.

**Not done / not verified.** Not looked at on a real phone. The constellation's per-frame cost at 3x was not re-measured here (the 2026-11-25 measurement was 3.1 ms for a full-frame 3x store, inside a 16.6 ms frame). Remaining unconverted canvases are unchanged: `media` posters, `cosmos` signs/mandalas/planet nodes/cr-icon/hero-wheel, `honors` auth-gauge, `profile` char-canvas and genealogy tree, `omega-animated.js`, `omega-graphify.js`, `omega-confetti.js`.
