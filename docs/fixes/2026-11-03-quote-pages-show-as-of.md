### pulse and investment show when a quote was fetched (2026-11-03)

**Why.** After #1149 `market-price` returns `as_of` (when the server fetched the quote) and `stale:true` when it serves a cached quote because upstream failed. `pulse.html` still tagged every quote `LIVE`, which is false for a quote up to 5 minutes old and worse for one up to an hour old; `investment.html` said "live price loaded" with no time. A price that looks current when it is not is the same class as §8.1 class 9.

**Fix.** `pulse.html`: `fetchIndexPrice` returns `{price, asOf, stale}`; the `LIVE` tag is replaced by `as of HH:MM TZ` (gold when stale or untimed, green otherwise), `STALE · as of …` when flagged stale, and `TIME UNKNOWN` when the server sent no `as_of` (an older deploy, or an unparseable value). The gold and oil ticker values carry the same text as a `title`. `investment.html`: the lookup message states the time, says STALE when flagged, and asks the member to confirm the price before relying on it. The time is the server's fetch time, not the page's.

**Verified.** Headless Chromium render (verify-in-browser harness, `market-price` stubbed per symbol): fresh XAU -> `as of 09:59 PM UTC`; stale XAG -> `STALE · as of 09:30 PM UTC`; XPT with no `as_of` -> `TIME UNKNOWN`; failed symbols -> `UNAVAILABLE`; no literal `LIVE` tag left; `#tk-GOLD` title `as of 09:59 PM UTC`; investment message `AAPL — price loaded: $190.5 (STALE, as of 09:58 PM UTC). Confirm it before relying on it.`; page errors `[]` on both. `check-inline-js.py`, `i18n-contract.py`, `silent-failure-detector.py`, `brand-glyph-check.py` pass.

**Not done / not verified.** The stubs, not the real function, supplied every quote: `TWELVE_DATA_API_KEY` is unset, so production still shows `—`/UNAVAILABLE and none of these labels is visible to members yet. The new strings are English-only and not in `i18n.js` (the surrounding page strings are not either). Time is shown in the viewer's zone. Equity names that the CoinGecko path returns are unchanged and carry no `as_of`. The footnote at `pulse.html:107` was not reworded.
