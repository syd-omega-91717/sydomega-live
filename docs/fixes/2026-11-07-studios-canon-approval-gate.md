### Studios canon: approval-gated delivery, concise Worlds page (2026-11-07)

**Why.** The owner's rule: nobody sees any content without prior approval, and the interface says only what is necessary, with the rest in the guide. Two violations of my own making in #1194: the Worlds canon shipped as a public static file (`/config/omega-studio-worlds.json`, fetchable by URL; `bg.js` only hides the page), and the page carried paragraphs of explanation. Measured: `curl https://raw.githubusercontent.com/.../ACT_1.fountain` is HTTP 200 unauthenticated, so the repository itself is public (GAP_ANALYSIS §S).

**Fix.** New Edge Function `studio-canon` (`verify_jwt = true`, `auth.getUser()`, then `_shared/studio-access.ts` on the caller's `profiles` row). The request body is never read, so nothing selects what is served. The page (`omega-worlds.js`) asks it through `OmegaSB`; a refusal shows only "APPROVAL REQUIRED". The payload is `studio-canon/worlds-data.ts`, generated from the config file (`--write-function-data`) and failed by the validator when stale. The page no longer names the config path, so `scripts/vercel-build.sh` no longer ships it. Page text cut to labels; cards show name and status and the note opens on selection; explanations moved to a guide answer (`omega-guide.js`, tap to open). Open questions cut to one line each.

**Threat model (short).** Unauthenticated caller: 401. Authenticated, unapproved, rejected, expired trial, no profile row, profile read error: 403 or 503, never the payload (matrix of 15 cases run under real Node). Input injection: none, the body is ignored. Origin: CORS allows only `sydomega.com` and `sydomega.pages.dev` subdomains, and CORS is not the boundary, the JWT and profile check are. Cache: `no-store`. Payload size is fixed. Not run: the repo's `grill-me-codex` pipeline for auth work.

**Verified.** `python3 -m unittest scripts.tests.test_studio_canon_gate scripts.tests.test_studio_worlds` (29 tests): the approval matrix, `verify_jwt` present in `config.toml`, no `req.json`/`searchParams`, verdict before payload, page does not name the static path; loosening the predicate in a copy lets an unapproved user through, which the matrix would fail. `bash scripts/vercel-build.sh`: `public/config/omega-studio-worlds.json` absent and no file under `public/` contains "Speaker Verran" or "Karth Vael". Headless render: all five tabs and the filters work at 1280 and 375 with a stubbed approved session; with a stubbed 403 the page shows "APPROVAL REQUIRED" and the DOM contains none of the canon.

**Not done / not verified.** The function is NOT deployed and has not been called against the live project: it is `LOCAL_ONLY` and kept out of `supabase/config.toml` (the repo's auth contract lists only deployed functions there), so merging does not deploy it and `worlds.html` shows UNAVAILABLE until the steps in `supabase/functions/studio-canon/DEPLOY.md` are done. **Deploy first, then merge, or the Worlds page is dark for everyone, including the owner.** the `profiles` columns it reads are `is_owner, access_approved, is_rejected, is_trial, trial_expires_at`, read from migrations and `bg.js`, not confirmed live. The repository is still public: `docs/studios` and `config/omega-studio-worlds.json` remain readable on GitHub. Making it private is the owner's decision.
