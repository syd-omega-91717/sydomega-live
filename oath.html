◆ SHA-256 CRYPTOGRAPHIC SEAL
Every oath is hashed using SHA-256 via the browser’s native Web Crypto API (crypto.subtle.digest). No external libraries. The hash input is CATEGORY|text|ISO-timestamp. This produces a unique 256-bit fingerprint for every oath — collision probability <2⊃;−128.
♔ THE SOVEREIGN OATH PHILOSOPHY
An oath is not a wish or a plan — it is a sovereign declaration, binding through its utterance. The cryptographic seal externalises the binding: the hash is immutable once created, matching the nature of a true oath. You cannot un-speak what has been hashed into the ledger. The sovereign keeps their word because the ledger never forgets.

◈ IMMUTABILITY GUARANTEE
Oaths are stored in a Supabase PostgreSQL table with Row Level Security. Insert permissions are granted but UPDATE and DELETE are denied for oath records — only the platform owner can modify the ledger structure. The cryptographic hash ensures that even a database administrator cannot silently alter the text without changing the hash, which would be detectable by any holder of the original content.
