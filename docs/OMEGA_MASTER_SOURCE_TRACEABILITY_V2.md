## 5. Critical contradictions resolved

### 5.1 Historical microservice/React/Prisma stack vs current production stack
The Master Prompt contains a React/Vite/React Native/Express/Prisma/microservices/Docker/Kubernetes architecture. The current production system is a framework-free static estate with Supabase and Vercel. The correct resolution is **not** to rewrite the working production system merely because the historical prompt specified another stack. Those sections become architecture history, backlog/options, or benchmark requirements unless a migration is separately approved and evidenced.

### 5.2 Provider/deployment claims
Source statements such as Render/Vercel/Netlify deployment or specific provider integrations are not evidence that those providers currently deploy the production system. Current provider state controls.

### 5.3 Financial ownership/control claims
Statements about absolute ownership, fixed percentages, automatic liquidation, sovereign currency, or guaranteed financial control are not treated as production facts. They require legal, financial, technical, and provider evidence and must not be displayed as live balances/rights without such evidence.

### 5.4 Sovereign/physical/cyber claims
Mars ledgers, orbital infrastructure, biological immortality, neural thought interfaces, legal immunity, offensive cyber warfare, physical defenses, molecular manufacturing, and simulation-of-reality control are retained as vision/lore/future concepts unless independently proven. They are not acceptable as LIVE product claims.

`SOURCE → NORMALIZED ID → DOMAIN → REQUIREMENT TYPE → CURRENT IMPLEMENTATION → AUTHORIZATION → TEST → CI CONTRACT → PROVIDER EVIDENCE → USER-FACING TRUTH STATE → RELEASE STATUS`

A requirement is not considered production-complete merely because code, SQL, UI, documentation, or a design exists.
