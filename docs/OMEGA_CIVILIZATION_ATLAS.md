# Ω SYD OMEGA 91717 — Civilization Atlas Contract

Purpose: extend the existing World + Cosmic Ledger into a governed hierarchy: Planetary body → World → Country → Empire/Faction → City → District → Service → Task.

This is platform information architecture and simulation, not a declaration of real-world sovereignty, territorial ownership or geopolitical authority.

The repository already has a governed Solar System Ledger, an 18-module World, a City surface, Factions/Sovereigns, Event Fabric, Evidence Graph, Mission State, and canonical capability/product registries. The Atlas adds hierarchy rather than another platform architecture.

Canonical planetary layer: Sun/Solar Core, Mercury, Venus, Earth, Mars Ledger, Jupiter, Saturn, Uranus and Neptune. Earth is the production world. Other bodies remain LORE/R&D unless independent evidence changes their state. The historical example duplicated Earth; the canonical runtime uses one Earth object.

Object contract: every node requires a stable ID, type, name, parent, truth state, purpose, provenance, linked route/capability where applicable, authorization boundary and lifecycle evidence.

Types: PLANETARY_CORE, PLANET, WORLD, REGION, COUNTRY, EMPIRE, FACTION, CITY, DISTRICT, SERVICE, RESOURCE, MISSION, TASK.

Service contract: service → capability → route → authoritative data → policy → event → evidence → verification. Existing production services must be reused; the Atlas must not create parallel copies of search, missions, marketplace, intelligence, payments or identity.

Task contract: TASK → AUTHORIZATION → ACTION → EVENT → EVIDENCE → MISSION STATE → REWARD/PROGRESSION. Existing Event Fabric, Evidence Graph and Mission State are the authoritative integration path.

Country and empire objects remain SIMULATION or LORE until actual legal/product decisions and evidence exist. They may have economies, governance rules, factions, cities, infrastructure and quests, but must not claim real legal jurisdiction, physical property ownership or governmental authority.

A mature city exposes districts, services, resources, infrastructure, organizations/factions, missions, events, transport/logistics, education, commerce, media, intelligence, governance, safety and environmental state. Population/activity telemetry is shown only when real and privacy-safe.

3-D rule: do not create a second WebGL renderer. Use the existing canonical 3-D owner for the first visual layer. For real geospatial scale, use interoperable open standards such as OGC 3D Tiles for massive 3-D content and CityGML/CityJSON for semantic city models and digital twins. Evolution: current governed symbolic hierarchy + existing 3-D Solar System; next procedural city/district scenes tied to platform objects; scale streamed geospatial tiles + semantic city objects + realtime state overlays.

Truth states: PRODUCTION, RUNTIME-VERIFIED, SIMULATION, LORE, R&D, UNVERIFIED, BLOCKED. Never convert simulation or lore into production merely because it is visually impressive.

10/10 acceptance: data model, canonical owner, authorization, failure behavior, event/evidence path, automated test, deployment and live evidence must exist.

Initial surface: /world-atlas.html. It provides the nine-body planetary layer, Earth production world, simulated countries/empires/cities/districts, production service mappings, task definitions, hierarchy inspection and truth-state filters. Seed names are design data, not historical facts or legal claims.
