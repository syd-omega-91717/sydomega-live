### migration-history-contract counted a blank Remote column as applied (2026-11-03)

**Why.** `scripts/migration-history-contract.py` `parse_remote()` did `remote.add(match.group(2) or match.group(1))`: a `supabase migration list` row with a blank REMOTE column fell back to the LOCAL column, so a migration that existed only locally was counted as applied remotely and the "local migration versions missing remotely" branch could never fire. Found while testing the staging workflow: a 413-version sample with the last REMOTE blank printed "exactly synchronized". Two more defects in the same function: a line that did not match the row pattern was scanned for any digit run, which read the TIME column's `2026` as a version, and unrecognised row-like lines were skipped instead of failing. The `--remote-output` path had no tests (`test_migration_history_contract.py` covered only `--local`), which is how it stayed unseen.

**Fix.** `parse_rows()` reads the two version columns separately (either may be blank); the remote set is the REMOTE column only; a separator-and-digits line that is not a recognised row now fails closed ("could not parse"). `parse_remote()` stays as a thin wrapper. Eight tests added for the remote path, each passing case paired with a violator.

**Verified.** Before the fix the new tests failed 3 of 14 (local-only row, unparseable row, time-column leak). After: `python3 -m unittest scripts.tests.test_migration_history_contract` -> `Ran 14 tests ... OK`. On the 413-version sample built from the real migration files: all rows matching -> exit 0; last REMOTE blank -> `::error::local migration versions missing remotely  20261025100000`, exit 1. `--local` and `--help` unchanged.

**Not done / not verified.** The CLI's table was assumed to be `LOCAL │ REMOTE │ TIME (UTC)` with box-drawing or `|` separators, as the script and the production workflow already assume; no real `supabase migration list` output was available here to confirm. The CI job that would feed real output to `--remote-output` needs Supabase credentials and does not run in this repo's workflows.
