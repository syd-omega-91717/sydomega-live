### The platform map becomes a luminous, evidence-wired blueprint (stage 3 first slice) (2026-11-21)

**Why.** The owner asked for the platform to match the reference art (`assets/concept/board-01/02`, `reel-03`). Scored against the plan's §9 checklist, the v1 map met (b) only: 15 real, linked workspace nodes. It failed (a) the Ω was a flat disc with no halo or rays; (c) connectors were static dashed spokes with no hub-to-hub relation and nothing flowing; (d) there were no data panels; and the map sat below a hero card, so the first screen never showed it. (e) the 3-D matrix element and (f) ground colour were out of scope or already met.

**Fix.**
- `scripts/relations-build.py` → `config/omega-relations.json`: 65 hub-to-hub edges, each citing its evidence, either a page listed in both hubs' `WORKSPACES` or a Supabase table/RPC a page in each hub reads or writes. `profiles`, `ping_session`, `expire_trial`, `report_client_error` are excluded as plumbing (listed in the file). `--check` is a blocking CI step (`ci.yml`, `ci-local.sh` 2o3). A line is drawn only if the file lists it; a file that does not load draws none and the map says so.
- `omega-one-shell.js`: radiant core (CSS rays at 90 s/turn, breathing halo), curved luminous connectors that flow (gold = shared pages, cyan = shared data), weight ≥ 3 shown at rest (9 of 65), the rest light up with their hub. Pointing at or focusing a workspace dims the others and reads out the evidence ("ACHIEVE connects to: Ascend (4 shared pages · 3 shared data sets) …"). Two side panels (workspace sizes; strongest relations with the pages named) and four counters, every figure computed from loaded data with its source printed. Reduced motion: lines, rays and halo are still.
- `sovereign-core.html`: the shell mount moved above the hero card.

**Verified.** Real Chromium at 1440, 768 and 375: no horizontal overflow at any. `scripts/shell-check.js` extended with the blueprint checks (every drawn edge in the file with evidence; at rest = the weight ≥ 3 set; hover lights the hub's edges and reads the evidence; no file → no edges, 15 links remain; reduced motion). `scripts/tests/test_omega_relations.py` (8 tests, including a planted-violator test: five doctored edges are each refused). Defects found by rendering and fixed in this change: a global `a[href]` accessibility rule collapsed the panel rows (specificity); `omega-readmore.js` clamped the readout to 2 lines and injected a stray MORE chip (`data-no-clamp`); opposite hubs drew a straight line through the Ω (bend by chord length).

**Not done / not verified.** This is a slice, not a match. Still missing against the reference: (e) the 3-D matrix cube, panel chrome as dense as the boards, the Ω as a real 3-D signet (the CSS core is a stand-in; `omega-sculpture.js` mounts need a static `data-omega-sculpture` attribute and the shell builds its DOM at runtime), and on a 1440×900 screen the lower half of the blueprint is below the fold because the page header and the platform orrery title use ~300 px above it. "Similar to the images" has no measurement here beyond the §9 checklist; a pixel comparison to the boards was not attempted. An edge means two workspaces touch the same data, not that one feeds the other (a regex over source is a candidate list). Edges depend on source scanning, so a table used only through a loader script not named by `<script src>` is missed. Not tested on a real phone or GPU.
