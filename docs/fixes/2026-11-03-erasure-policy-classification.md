### Every member-data table is now classified for erasure, enforced in CI (2026-11-03)

**Why.** `docs/legal/ERASURE_PLAN.md` finding 9: nothing forced a person to classify a table added after the erasure prototype was written, so it would be silently deleted or silently kept. Finding 5: 29 tables carry `owner_id`/`author_id`/`created_by`-style columns and no `user_id`, so the prototype's sweep never reached them (for example `ai_conversations`, `team_messages`, `api_keys`, `storage_files`, `ai_documents`).

**Fix.** `config/erasure-policy.json` lists all 161 public tables (from `supabase/live-schema.json`, captured 2026-10-06) that carry a member column (`user_id`, `profile_id`, `member_id`) or a reference column, each with an `action` (`delete` | `anonymise` | `retain` | `pending_decision`), a `reviewed` flag and a reason. 122 are proposed `delete`; **39 are `pending_decision`**: the 10 retention-sensitive ones (`payments`, `billing_invoices`, `subscriptions`, `omega_service_orders`, `commission_contracts`, `consent_records`, `sovereign_events`, `platform_events`, `threat_events`, `sovereign_points_ledger`) and the 29 reference-only tables. **All 161 are `reviewed: false`.** `scripts/erasure-policy-contract.py` fails on an unclassified table, a stale entry, a bad action or an empty reason; with `--gate` it also fails while any row is pending or unreviewed. No schema, function or CI workflow changed.

**Verified.** `python3 -m unittest scripts.tests.test_erasure_policy_contract` -> 10 tests OK, including a violator for each rule and a test that runs the contract on the real files (so the existing CI unit-test step enforces it with no workflow edit). On the real files the default run passes (`161 tables classified, 39 pending a decision, 161 not reviewed`) and `--gate` correctly exits 1. Full `scripts/tests` suite: 1102 tests OK. `audit.py`: 0 critical. `config/` is not published (the build ships only config files referenced by shipped code or named in `public-config.txt`; nothing references this one).

**Not done / not verified.** The 122 `delete` rows are **proposals**, not reviewed. The snapshot is dated and may be missing newer tables, so "complete" means complete against 2026-10-06; production was not reachable to refresh it. Foreign keys were not examined. The classification is not yet used by any purge function: the migration is still blocked on decisions D1 and D2.
