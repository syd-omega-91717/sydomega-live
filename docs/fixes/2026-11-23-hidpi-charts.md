### Money-cluster charts were 1x bitmaps stretched on 2x/3x screens (2026-11-23)

**Why.** The owner asked for the visual graphics at "high standard and resolution". A canvas written as `canvas.width = W` has one backing pixel per CSS pixel, so on a phone or retina screen the browser stretches it and every axis label and legend letter is soft. Measured 2026-11-23: 72 of the 91 files that draw on a 2-D canvas never mention `devicePixelRatio`. Only the money cluster was fixed this round (9 canvases on 5 pages); the other 72 files were not touched.

**Fix.** New `omega-canvas-hidpi.js` (`OmegaCanvas.fit(canvas, cssW, cssH[, {size:true}])`): backing store = css size x ratio (ratio capped at 3), `setTransform` (never `scale()`, so a redraw cannot compound), the caller keeps drawing in CSS pixels. A canvas that has no CSS size of its own (`wealth.html`) passes `{size:true}` so it is pinned and does not double on screen. Loaded as a plain, non-deferred script tag before the inline scripts on `expenses` (5 canvases), `investment`, `revenue`, `treasury`, `wealth`. `bg.js` is untouched.

**Verified.** `scripts/verify-hidpi-charts.js`: **45/45** on the fix, **36/45** against pristine `origin/main` (served from a worktree), measuring at 1x, 2x and 3x that the CSS size is identical (layout unchanged, not doubled), that the backing store is exactly 2x/3x the 1x store, and that painted coverage is not lost. Mutation-tested: dropping `setTransform` fails the painted-coverage checks on the expenses charts; dropping `{size:true}` on wealth fails "CSS size is the same at 1x, 2x and 3x". Looked at, not only counted: the same axis-label region of `expenses.html` at 3x device scale, before (soft, upscaled glyphs) and after (crisp), identical layout; backing store 766x200 became 2298x600 with the CSS size unchanged. `scripts/tests/test_hidpi_charts.py` pins the helper (cap, transform), one non-deferred tag per page before any call, the call count per page, and runs the browser suite; removing a page's tag fails it.

**Not done / not verified.** (1) 72 other files draw on canvases without handling the ratio; this is not platform-wide. (2) Software Chromium at emulated device scale factors, not real retina or phone hardware; the visual comparison is one chart region on one page. (3) Memory: a 3x store is 9x the pixels of a 1x one on the largest chart (766x200 is small, so this is not measured as a cost). (4) The tolerance is 2.5% because layout varies about 1% between device scale factors. (5) Not deployed.
