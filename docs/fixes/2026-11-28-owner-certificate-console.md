### Owner certificate console on approvals.html (blueprint 20/238/256, Phase 1) (2026-11-28)

**Why.** `public.omega_issue_certificate` (owner + aal2 + `is_owner`, writes an event row) was granted to `authenticated` on 2026-10-12 and no page called it, so no governed certificate could be issued from the product. The obvious fix, certifying a member when their stage progress reaches a band, would issue fabricated credentials: the legacy progression RPC takes a member-supplied task string and raises `axis_a/b/c` (`0001_omega_master_deploy.sql` ~275-345; later migrations were not re-read), and the stage achievements are seeded `no_auto_award` / `requires_verified_progress` (`20261002031000`). Decision record: `docs/decisions/stage-certificates/PLAN.md`.

**Fix.** `omega-certificate-console.js` (new) mounts in `approvals.html`'s Operations tab (`#cert-console`). The owner chooses a member and an active achievement, writes evidence (required, at least 10 characters), confirms, and the module calls `omega_issue_certificate` itself. Success is shown only when the returned row has a `certificate_number`; a refusal is shown with its meaning; an aal2 refusal steps up once through `OmegaMFA` and retries once. `approvals.js`'s `rpcOnce` was not reused: it counts a call as successful only when the result has `ok:true`, and this function returns a row, so it would have reported every success as a failure. No migration, no new table or RPC, no member write path, no `achieve.html` change (that page says it does not mint awards).

**Verified.** `node scripts/verify-certificate-console.js`: PASSED 9 of 9 in a real render of `approvals.html` as the owner (returned row reported with its number and the exact RPC arguments; server refusal not called issued; no-row-no-error not called issued; aal2 step-up once and one retry; missing evidence never reaches the RPC; a member name containing markup stays text; no page errors from this module). `python3 -m unittest scripts.tests.test_certificate_console`: static contracts OK, browser case OK with `OMEGA_CERT_BROWSER=1`. `schema-dictionary.py`, `grant-contract.py` and `audit.py` pass.

**Not done / not verified.** (1) The live database was not reachable (the connector lists only the non-canonical project), so the live body of `omega_issue_certificate` and whether the legacy progression RPC is still self-attestable were not checked. (2) No Codex review ran (usage limit); `PLAN.md` is `AWAITING-HUMAN-REVIEW` and its review file is a self-review. (3) The render uses a stub, so it proves the client wiring, not production RLS or the real aal2 flow. (4) Not built: revoking from the UI (needs a certificate id that no read path returns to the owner), a member-facing stage-band automation (blocked on a server-graded evidence source, an owner decision), and a certificates list for the owner. (5) `approvals.html` under this harness raises `t is not defined` from `approvals.js`, which also happens on `origin/main`; not investigated.
