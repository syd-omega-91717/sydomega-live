## Truth boundary

A source statement can be:

- SOURCE — exists in the corpus.
- LIVE — backed by authoritative production state.
- CALCULATED — derived from authoritative inputs with a disclosed formula.
- SIMULATED — intentionally modeled.
- DESIGN_PROPOSAL — original architecture proposal awaiting implementation.
- IMPLEMENTED — code and contracts exist and automated verification passes.
- PARTIAL — some but not all required production contract exists.
- BLOCKED — implementation is blocked by an external dependency or failed gate.
- UNVERIFIED — implementation may exist but production evidence is missing.
- UNAVAILABLE — required authoritative state cannot currently be obtained.
- LORE — narrative content only.

Visual presence never upgrades a source concept to LIVE.

## Historical architecture versus current architecture

The April 2026 Master Prompt contains a React/Vite/Express/microservices/Prisma/Redis/Expo build specification.

That historical proposal is preserved as source material.

It is not the current production architecture.

The current platform should continue the framework-free static/Supabase/Vercel architecture and selectively adopt the underlying engineering principles where they improve the existing system. A rewrite would create unnecessary migration risk and violate the project's continuity requirement.

## Production gate

A capability is not complete merely because a page or configuration entry exists.

Before a source requirement is marked production-complete, the repository should provide:

1. authoritative implementation;
2. authorization/policy enforcement;
3. failure handling;
4. observability;
5. automated verification;
6. deployment evidence;
7. production evidence where the capability depends on live infrastructure or external providers.

## Canonical integration rule

New systems must reuse the existing canonical identity, event, evidence, mission, capability, lineage, atlas and progression systems.

No parallel identity system, event bus, evidence graph, mission state, capability registry, WebGL renderer or object model may be introduced merely to satisfy a source concept.

## Engineering consequence

The source corpus is treated as a requirements and provenance layer, not as an authorization layer or runtime state store.

This allows the platform to preserve the extraordinary original vision while maintaining production-grade truthfulness.
