### The particle field is lighter on phones and unchanged on desktop (2026-11-06)

**Why.** `docs/PLATFORM_COMPLEXITY_ANALYSIS.md` section 6 profiled the platform at a phone-class setting (390 px, 4x CPU): `vendor/tsparticles-slim.js` was 7.2% of script self-time on `dashboard` and 13.7% on `journal`. The owner picked this layer for the first visual trim. The element configs set a fixed particle count, a 40 fps cap and a hover-repulse interaction regardless of device.

**Fix.** `omega-particles.js` `buildConfig` now reads two helpers. `isLight()` is true for a viewport of 700 px or less, `navigator.deviceMemory <= 4`, or `navigator.hardwareConcurrency <= 4`; it halves the configured count (floor of 8) and caps at 30 fps (the same cap `omega-genesis.js` already uses). `canHover()` gates hover-repulse on `(hover:hover)`, since a touch screen has no hover to react to. Otherwise unchanged: same element palette, shapes, motion, fade-in, vendored engine, and the reduced-motion early exit. `scripts/tests/test_particles_light_profile.py` pins it.

**Verified.** Render, `journal`, 390 px mobile context, 4x CPU, 7 s after load, three runs each, committed file vs this change, self-time of `tsparticles-slim` plus `omega-particles`: before 439 / 363 / 306 ms (median 363), after 345 / 259 / 220 ms (median **259, -29%**); particles 17 -> 9, fps cap 40 -> 30, hover true -> false. Desktop-class profile (`hardwareConcurrency` 8, `deviceMemory` 8, 1280 px): particles 52 -> 52, fps 40 -> 40, hover true -> true, config identical (timing 438 vs 377 ms is noise). Unit tests, `audit.py`, `module-contract.py`, `omega-registry.py --check` and `verify-runtime.js` pass (see PR).

**Not done / not verified.** About 100 ms of roughly 2,000 ms of script time on `journal`, so roughly 5% of the page's script cost: a real but small gain. A visual comparison by eye on a real phone was not made; the field is visibly sparser on small screens, which is the intended trade. No real phone, network or GPU paint cost was measured, and run-to-run spread is wide (306-439 ms before). The other candidates from the profile (per-glyph `shadowBlur` in the icon loop, the `bg.js` background canvases) are untouched.
