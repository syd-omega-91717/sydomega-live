# Ω ORDER Workspace Consolidation

`/order.html` is the canonical discovery surface for family, heritage, community hierarchy, factions, civilization views and governed approvals.

## Specialist routes retained

- `/family.html` — private family and relationship surfaces
- `/hall.html` — order roster/certificates/events
- `/sovereigns.html` — leaderboard/throne/statistics
- `/factions.html` — faction and knight surfaces
- `/city.html` — living-city presentation, districts and governance
- `/approvals.html` — governed approval queues
- `/interface-omni.html` — administrative control deck
- `/heritage.html` — historical/cultural archive
- `/bloodline.html` — lineage presentation

## Safety boundary

The workspace is navigation, not an authorization layer. It does not approve members, change platform flags, alter private family data, mint credentials, or manufacture rankings/counts.

Existing RLS, owner checks, AAL2 requirements, governed RPCs and specialist-page authorization remain authoritative.

## Migration rule

No specialist page is deleted solely because it is linked from the hub. Absorption requires capability parity, deep-link preservation, authorization verification, analytics continuity and production verification.
