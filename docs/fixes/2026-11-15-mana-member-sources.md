### Mana measures the member's own recent activity, not a platform-wide table (2026-11-15)

**Why.** The owner defines mana as the user's inner power gained by using the platform (the repo's own definition: `config/omega-relearn-sigil-mana.json`, "non-financial ... neverMeans money"). `life.html`'s mana did not measure that, from source:
1. FOCUS (`caps*8`) and EXECUTION (`caps*6`) were fed from `capability_registry`, a platform-wide table (no `user_id`, "authenticated reads"), through `lifecycle_status==='ACTIVE' || health_status==='HEALTHY'`. `0061_omega_capability_registry.sql:30-31` only allows lowercase values (`'live'`..., `'healthy'`...), no later migration changes it and nothing writes uppercase, so the filter matched nothing (class 2: a value that does not exist). Fixing only the case would have given every member the same platform-wide number.
2. COLLABORATION and part of EXECUTION came from `omega_member_mission_state.status==='ACTIVE'||'IN_PROGRESS'`; the table allows only `'active','completed','failed','cancelled'` (`20260928135609_...:42`), so that matched nothing either.
3. CREATIVE was `explicit*4` = points for having filled in sign/element/agent: profile completeness, not use.
4. Nothing was windowed, so nothing faded, and the page's queries were `limit(20)`/`limit(50)` of all time.
Not checked against live data (access refused).

**Fix.** `calculateMana` in `omega-relearn-sigil-mana.js` now takes only the member's own timestamped rows and a trailing window (30 days, recomputed on read, nothing stored, so mana rises with use and fades without it): FOCUS = active days (tasks, evolution events, platform events) / window; LEARNING = tasks with points x10; COLLABORATION = missions currently active (touched in the window) x7; EXECUTION = missions completed in the window x10; **CREATIVE = null** (no recorded source exists: shown as "—" with a note, never filled in). Rows with no or invalid timestamp, outside the window or in the future are ignored; mission status is matched case-insensitively. The total averages only the sourced components. `omega-life.js` fetches those windowed rows (`.gte(...)`, limit 1000), reads missions with their timestamps, and if any source read fails shows "—" and says so instead of a number. `capability_registry` is still read for the page's SERVICE count, but no longer feeds mana. `config/omega-relearn-sigil-mana.json` sources updated.

**Verified.** `node scripts/tests/test_omega_relearn_sigil_mana.js` PASS (rewritten): 5 learning tasks -> LEARNING 50; 7 distinct active days -> FOCUS 23; 1 active mission -> COLLABORATION 7; 2 completed -> EXECUTION 20; CREATIVE null; a member with 14 platform capabilities and sign/element/agent but no activity -> total 0; two members with different activity differ; the same activity read 31 days later -> 0; out-of-window, undated, bad-date and future rows -> 0; `'COMPLETED'` counts; bad input types do not throw. `test_omega_life_surface.js` PASS with new asserts (no capability/profile inputs to mana, no uppercase status literals). Headless Chromium, `life.html`: empty stub -> `0/100`, CREATIVE "—" with note, 0 errors; stub with 4 learning tasks on 4 days + 1 evolution + 1 platform event + 1 active + 1 completed mission and 20 healthy capabilities -> `19/100` (FOCUS 20, LEARNING 40, COLLABORATION 7, EXECUTION 10), the capabilities changing nothing, 0 errors; phone 390px no overflow. A first render wrapped "no source yet" to three lines and the source line was cut by the page's MORE clamp: shortened and moved the note under the bars.
