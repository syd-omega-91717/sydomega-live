### Six canvases re-measure, atlas un-stacked, 8 pages back over the contrast floor (2026-11-24)

Three items recorded OPEN in `GAP_ANALYSIS.md` §S by the hi-DPI work, closed here.

**1. Six canvases measured before their layout settled** (CLAUDE.md §8.1 class 3). `architect.html`, `knowledge.html`, `mindmap.html`, `queue.html` (topology), `wallet.html` (allocation chart) and `atlas.html` read `offsetWidth` once, while the approval guard still hid the shell or before flex had distributed width, so the store was sized for a box the canvas never had (architect 958x520 in 820x445; mindmap 944x900 in 442x422, which skewed `offsetX` hit-testing by that ratio; atlas 0x0). *Fix:* a `ResizeObserver` on each canvas's container re-runs the page's own resize/draw handler when the container's width changes (first callback kept, rAF-throttled). *Verified:* the hi-DPI harnesses had carried a `stale: true` escape hatch for these six; it is removed from all five chart entries and the mindmap prep no longer calls a resize by hand, and `scripts/tests/test_hidpi_charts.py::Settles` pins the observer in each file.

**2. `atlas.html` stacked every node on one point.** `fitAll()` ran while the canvas was 0x0, so the fit scale came out 0; `seedDefault` also seeded around (400,300) while gravity pulled to the canvas centre. *Fix:* `fitAll` defers (`pendingFit`) until the canvas has a size and `resize()` completes it; the default seed is centred on the origin. *Verified:* the pointer harness un-skips atlas (no seeds, resize event as the reveal) and checks hit-testing across device scales. Pinned by `test_hidpi_charts.py::AtlasFit`.

**3. Eight pages under the runtime sweep's 3:1 text floor** (`design-system`, `graph`, `healthz`, `offline`, `reset`, `verify-deployment`, `verify-modules`, `visual-atlas`). *Cause, found by tracing the computed value, not by grep:* `config/page-character-manifest.json` gave the `system` archetype `accent: #8B0000` and two archetypes `secondary: #8B0000`; `omega-page-world.js` writes them inline on `<html>` (so no stylesheet can override them) and `omega-platform-experience-v6.css` paints accent/secondary as heading and label text: 1.78-1.95:1 on the near-black page. Editing the CSS alone changed nothing (first attempt, measured); the manifest is the owner. *Fix:* those three values are now `#CF6760`, the platform's existing `--crim`, with matching glow/line and the v6 CSS defaults; `graph.html`'s Ares colour likewise. The sweep also reported six 1.03-1.05:1 element labels in `graph.html`: dark `#020206` text drawn over its own bright d3 disc, which the sweep could not see because the disc is a sibling, not an ancestor. That was a measurement gap, not a page bug, so `scripts/verify-runtime.js` now judges SVG text against a sibling circle/ellipse/rect whose box contains it; its self-test gained two fixtures (on-disc passes, the same label off the disc still blocks) and still bins correctly (11 known ratios).
*Verified:* `node scripts/verify-runtime.js --pages` on the eight pages: 8 FAIL before, `RUNTIME VERIFICATION: PASS (8 pages)` after. `test_omega_experience_v6.py` now rejects `#8B0000` as an archetype accent or secondary (the old test pinned it as canonical).
