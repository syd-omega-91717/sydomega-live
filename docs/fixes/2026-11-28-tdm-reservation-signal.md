### A machine-readable AI-training opt-out, instead of attacking other models (2026-11-28)

**Why.** The 999-point ledger's "poison other AIs' training data" idea is rejected (it harms real people and third parties). Its legitimate core is "stop my content being used to train models without permission". The honest mechanism is a reservation of rights, not an attack. Measured state: production `https://sydomega.com/robots.txt` (fetched via Firecrawl, 200) is a Cloudflare-managed file with `Content-Signal: search=yes,ai-train=no` and Disallow rules for the named AI-training crawlers, so a crawler-level opt-out already exists at the edge. What did not exist is the W3C TDM Reservation signal (`/.well-known/tdmrep.json`), which is the machine-readable form the EU DSM Directive Art. 4(3) points at and which does not depend on a crawler honouring a user-agent list. Separately, the repo's own `robots.txt` is not copied by `scripts/vercel-build.sh` (its find list has no `.txt`), so the repo copy (Allow /, Disallow /admin/ /owner/ /private/ /api/) is not the policy production serves.

**Fix.** Added `.well-known/tdmrep.json` (`[{"location":"/*","tdm-reservation":1}]`). The build's `*.json` find ships it with no build change. `scripts/tests/test_tdm_reservation.py`: file validity, a checker with five planted-defect controls, and a real `vercel-build.sh` run proving the file lands in `public/.well-known/`.

**Verified.** `python3 -m unittest scripts.tests.test_tdm_reservation`: 3 tests OK (including the real build). `omega-registry.py --check` matches; `audit.py` 0 critical / 8 warnings (baseline); `contract-suite.py` 99 gates, 0 failing.

**Not done / not verified.** (1) Not verified that production serves it: that needs this merged and deployed; fetch `/.well-known/tdmrep.json` after the deploy. (2) The `tdm-reservation` HTTP response header is not added (it needs a `_headers` rule and a deploy to confirm). (3) Opting out of AI training for the whole site is the owner's policy call; reserve fewer paths by editing the file. (4) The repo `robots.txt` / production mismatch is flagged, not changed: Cloudflare's managed file is the live policy, and shipping the repo copy could alter it. (5) This is a request, not enforcement: a crawler can ignore it.
