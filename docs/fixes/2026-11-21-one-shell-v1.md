# One-shell v1: the Command Core becomes a map and a stage that hosts the platform's pages

Date: 2026-11-21. Stage 2 (first version) of `docs/OMEGA_ONE_SHELL_PLAN.md`. Stacked on #1473 (`OmegaPanels.open(url, host)`).

## What a member gets

On `sovereign-core.html` (the Command Core), above the existing domains grid, one surface with three views on one hash route:
`#/` the MAP (15 workspaces around the Omega), `#/hub/<hub>` a workspace's pages, `#/p/<page>` a page shown in place. The URL path never
changes, back/forward work, focus moves to the heading, a live region announces each change. Existing page content is untouched.

## Parts

- `omega-one-shell.js` (new, ~400 lines, ES5 style, no framework): router, three views, link interception, CSS (`ons-` prefix), reduced-motion.
- `omega-single-page-workspaces.js`: publishes `window.OmegaWorkspaces = {hubs, panels, label}` (copies) and fires `omega:workspaces-ready`, so the
  shell reads the hub table from its one owner and keeps no copy.
- `sovereign-core.html`: `<section data-omega-one-shell>` + the script tag.
- `scripts/tests/test_omega_one_shell.py` (11 static tests), `scripts/shell-check.js` (32 browser checks, run by hand), `OMEGA_SKILL_REGISTRY.md` regenerated.

## Rules it enforces (and the tests that pin them)

- A page is hosted only if `config/omega-panel-eligibility.json` says `hostable`. Unknown, `excluded-pending-review` (kyc, payments, privacy, wallet,
  subscriptions, marketplace), `standalone-by-policy` (account, terms, ...) and `navigates-away` (enterprise, ...) become a plain link. If the registry
  cannot be read, nothing is hosted.
- The shell never hosts its own page, and never hosts a workspace page (its tabs are mounted by pathname); a workspace used as a page routes to its workspace view.
- No data becomes markup (no innerHTML/outerHTML/insertAdjacentHTML/document.write/eval); route keys are validated against `^[a-z0-9-]+$` first.
- The map draws only what the workspace table states: each workspace's membership (15 lines) and page counts. Page-to-page relations are NOT drawn (measured: 113 of 242
  pages link to another page). Nothing on it is invented.

## Mistakes made on the way, and what caught them

1. **I overwrote an existing module.** I named the new file `omega-shell.js` without checking; that file is the repo's async loading/empty/error/retry shell
   (`OmegaShell.bind`, used by `bg.js`, `sw.js`, `omega-a11y.js`, `who.json`). `git diff` showed 292 deletions; restored from HEAD (byte-identical, verified) and renamed mine to
   `omega-one-shell.js` / `data-omega-one-shell` / `ons-`. A test now pins that the two stay separate. My first CSS prefix `osh-` also collided with `omega-share.js` (`osh-grid`).
2. **Detached stage.** My first `leavePage()`/`notice()` cleared the engine's host, but the engine keeps a reference to the stage it created inside; the next `open()` would have loaded into a
   detached node. Found by reading the code before running it; the host is now never cleared and notices have their own element.
3. **The shell tried to host itself.** A `#top` link resolved to `/sovereign-core.html`, which the registry lists as hostable, so it routed to `#/p/sovereign-core` and embedded the Command Core
   in itself (and its scripts then threw). Found by the browser check; fixed (same-document links are left alone; the shell's own page is never hostable) and pinned by a check and a test.

## Not done / limits

- It is a first version, not the finished experience. The map is a ring of links with membership lines, not the dense composed blueprint of the reference art (stage 4 is the visual pass; the checklist in the plan, section 9, still needs your approval).
- The existing "Sovereign domains" grid and agent panels are still on the page; nothing was removed. Stage 5 makes in-shell the default navigation.
- Pages run in the shell's document: a page's own `location.href=` leaves the shell (100 of 218 hostable pages contain such code). Links to other hostable pages are intercepted;
  programmatic navigation cannot be. `water` and `mood` still leave one interval running after close (pre-existing).
- "Hostable" is for the signed-in member stub. An owner-only page may behave differently for a real member; not tested with real roles.
- Not verified: real GPU/phone feel, production, the page contract's `script_evidence` for `sovereign-core` (the audit passes unchanged; I did not add the new script to that list).
- No CI job runs `scripts/shell-check.js`.
