SOVEREIGN AI ARCHITECTURE
THE 12-AGENT MESH
Each of the 12 sovereign agents is bound to a zodiac sign, element, and domain. The agent assigned to your sign is your primary interface — it speaks in the voice calibrated for your cosmological alignment. All 12 agents share the same edge function backend (the concierge) but receive distinct system prompts based on their role, element, and domain.
CONCIERGE EDGE FUNCTION
Agent queries route through the Supabase Edge Function named 'concierge'. The API key never appears in client code. The edge function receives the message, a system override with the agent's voice and role, and the member's ORACLE_CTX — sign, axes, authority, tier, and rank — so agents answer in the context of the member's actual standing.
AUTHORITY CONTEXT
Every agent message includes the member's authority score (AUTH = sqrt(A³+B³+C³)×φ/e) and sign. This allows agents to calibrate their responses to the member's actual position in the sovereign hierarchy — an APEX SOVEREIGN member receives different guidance than an INITIATE. Authority context is never persisted by the edge function.
AGENT DEFINITIONS
Agent identities — name, sign, element, olympian, voice, greeting, and domains — are loaded from /omega-agents.json at boot. This file is static and served from the deploy root. Updates to agent definitions require only a file update; no code change is needed. The 12-agent configuration maps one-to-one with the 12 sovereign signs.
