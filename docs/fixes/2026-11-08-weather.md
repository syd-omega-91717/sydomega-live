### Weather: location was blocked site-wide, unknown codes read as sunshine, and two copies of the table disagreed (2026-11-08)

**Why.** The user reported "the weather is not working as it should". There is no weather page; weather is two surfaces that both call Open-Meteo: the dashboard's daily-brief panel (`omega-daily-brief.js`, needs the browser's location) and the pulse page's six-city card (`pulse.html`).

**Reproduced first, in a real browser** (location permission granted, API stubbed, dashboard served with the production header): the panel said "LOCATION PERMISSION DENIED". Cause: `vercel.json` sends `Permissions-Policy: geolocation=()`, which denies location to every page on the site, so no member could ever get past it however they answered the prompt. With the header relaxed the panel worked but exposed three more defects.

**Defects and fixes.**
1. `geolocation=()` became `geolocation=(self)` (same-origin pages may ask, the browser still prompts, camera, microphone, payment and usb stay denied; only the dashboard calls the API and only after the member presses its button). `security-headers-contract.py` only requires the header to exist, so no contract changed.
2. Any code the dashboard's private table lacked was shown as "CLEAR" with a sun: snow showers (85) at -3 C read as sunshine. Now an unknown code reads "Conditions unavailable", and all 28 documented Open-Meteo codes have labels.
3. The pulse page had a second, different, smaller table (no drizzle 53/55, heavy snow 75, showers 81/82, hail 96 ...: "Unknown"). There is now one table, `omega-weather.js`, used by both pages; a test fails if a second copy appears.
4. A western or southern position was printed under the wrong hemisphere ("40.7N -74.0E" for New York); now "40.7N 74.0W".
5. On the pulse page one failed city blanked all six (`Promise.all`); now `allSettled`, the failed city says "Unavailable right now". A calm wind (0) was printed "--"; now "0".
6. The dashboard button stayed disabled after a success or a failed fetch, so a member could not retry; every location error was reported as "permission denied" even for a timeout. Now the button re-enables and the three error codes read as what they are, with a 10 s timeout.

**Verified.** `test_weather.py` (8 tests: all documented codes labelled, unknown never "clear", hemispheres, encoded URL, calm wind, one table in the platform, the header, error messages). Real browser, same reproduction: with `geolocation=(self)` New York at code 85 reads "40.7N 74.0W - LIGHT SNOW SHOWERS - Wind 0 km/h", the button re-enables; with the old header it still (correctly) says permission denied. Pulse page at 1280 and 375 wide: six cards with one city returning HTTP 500, every code labelled, no "Unknown", no "--", no overflow, no page errors.

**Not verified.** The live site (this session cannot reach it) and a real device's location prompt. The header change takes effect only once deployed. Open-Meteo itself was stubbed.
