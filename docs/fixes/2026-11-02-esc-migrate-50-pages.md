### Shared escaper: 50 pages moved off their own esc(), each proven equivalent first (2026-11-02)

**Why.** 100 root files defined their own `esc()`; #1135 added `omega-esc.js` and migrated 4 pages as a pilot. This moves the rest that can be moved safely, so the fix for the next escaping bug has one place to go.

**How, and what makes it safe.** A one-off codemod (kept out of the repo; the method is here). A page is touched only if (a) `esc` is defined or assigned exactly once in it, (b) the definition is a plain column-0 statement in an inline script with no `src`/`defer`/`async` and a plain or module type, (c) the script does not start with a `"use strict"` directive, and (d) **the local function behaves identically to the shared one**: both are executed in Node over 18 inputs (empty/null/undefined, 0, 1.5, booleans, NaN, -0, a BigInt, `&amp;`, a string with `& < > " '`, an object with `toString`, an array, a line separator, non-ASCII) and compared character by character. Of 54 candidates, **50 were provably equivalent and migrated**; skipped and listed: 7 whose definition is not a plain top-level statement, 3 that define `esc` more than once (`dashboard`, `family`, `profile`). The 4 "differences" the check printed were the already-migrated pilot pages, whose alias line it could not evaluate outside a browser (`window is not defined`), not real differences. Module scripts get `const esc = (window.OmegaEsc && OmegaEsc.esc) || (() => '');` at the top of the script; classic scripts get the `var` form (a `const` could collide with another classic script's global `esc` and kill the whole script). Each page gets one `<script src="/omega-esc.js">` immediately before that script. Pages whose escaper is named differently (`escapeHtml`, `escH`, ...) and every `.js` module are not touched.

**Verified.** A browser sweep of all 50 pages on `main` first, then on the migrated tree (same signed-in stub): **0 page errors before, 0 after**; rendered text length unchanged on all 50; the 20 classic pages that expose a global `esc` return the identical escaped string for the same input. Two things in the first comparison looked wrong and were run down instead of ignored: (1) `enterprise.html` reported no helper because the page redirects a non-owner to `/dashboard.html`, so both sweeps had measured the dashboard; re-run with an owner session (the stub served with `is_owner:true`) it stays on its own page, the helper loads (`undefined` on `main`, `object` migrated), text length is identical (2842) and there are 0 errors. (2) `lab.html` and `subscriptions.html` showed about 280 fewer elements; four runs on unmodified `main` alone flip between the same two counts (`lab` 3238/2950/2956/2940, `subscriptions` 3281/2991), so it is a timing-driven layer, not the change. `esc-copy-ratchet`: 98 → **48** definitions in 46 files. `config/omega-page-contract*.json` regenerated with `--promote` (one new script entry per page). New tests in `test_omega_esc.py` check every adopting page: helper loaded exactly once, before the alias, alias fails closed, no local copy.

**Not done / not verified.** 46 files still carry their own escaper: all `.js` modules (they run when injected by `bg.js`, possibly before a page's helper exists, so they need their own decision), the 10 skipped pages, and differently-named ones. The sweep proves the pages load and render the same with the stub; it does not exercise every code path that calls `esc` (the equivalence test is what covers that). Signed-in stub only, no Safari/Firefox.
