### The eighteen-node map, drawn as an illustration (omega-node-map.js) (2026-11-23)

**Why.** The owner asked for "the 18-node map as an illustration". Before drawing anything: the brief's "18 Master Modules" (Platform Core, Consultancy, Gaming ... Hierarchy) are the eighteen entries of `OmegaWorldEngine.modules` (`omega-world-engine.js`) name for name and in the same order (checked by printing the registry: CORE, CONSULTANCY, GAMING, ACHIEVEMENTS, FAMILY, MEDIA, BLOCKCHAIN / NFT, COMMUNICATION, HOROSCOPE, NEWS, HERITAGE, PROGRESS, CREDENTIALS, LEGAL, ELEMENTAL, INVESTMENT, INTELLIGENCE, HIERARCHY), and `SCENES.world` already draws them in 3-D on world.html. So this is not a new list and not a new feature area: it is a second medium for an existing one. A second hand-typed list would have been CLAUDE.md 8.1 class 8, so the new module reads the registry and copies nothing.

**Fix.** `omega-node-map.js` (new, ~11 KB, pure ASCII, no network): `<div data-omega-node-map>` becomes a flat SVG -- the Omega signet in the middle, eighteen numbered nodes in three rings of six (the same grouping `SCENES.world` uses), a spoke to each, each node stroked in its registry accent -- beside a numbered legend of eighteen real `<a>` links. The SVG is `role="img"` with an accessible name that says it is an illustration and not a live status display; the figure caption says the same on screen and links to world.html, which owns live route status. Hover or keyboard focus on a legend entry lights its node; clicking a node follows the same link. Nothing travels a spoke (movement would read as data flowing); the only motion is a slow halo on the signet, inside `prefers-reduced-motion:no-preference`. Below 640 px the in-map labels step aside and the drawing is cropped to fill the width; the legend carries the names. If the registry is absent the map draws nothing and says so. Mounted on `sculpture.html` (two script tags and one mount); `bg.js` is not touched.

**Verified.** `node scripts/verify-node-map.js` 26/26 (software Chromium, harness Supabase stub, files served via `route()`): the eighteen drawn nodes' numbers, names, ids and stroke colours equal the registry's, in order; the legend's hrefs equal the registry's, in order; no label overlaps another label, another disc or the signet and none leaves the drawing (`getBoundingClientRect`); every disc is the topmost element at its own centre; hover/focus/click behave; the only looping animation is the halo and nothing animates under reduced motion; 375 px has no horizontal overflow and all discs sit inside the cropped viewBox; with the registry blocked it draws nothing and throws nothing. `scripts/tests/test_node_map.py` adds 12 static contracts and wraps the browser run. **The suite was mutation-tested**: outer ring offset reverted (overlap) -> fails; registry reversed -> 4 failures; hrefs replaced -> 2 failures; a spoke animation added -> fails; a fabricated "99.9% uptime" in the caption -> fails; a fallback list when the registry is missing -> fails. Two mutations were NOT caught by the browser run and are covered otherwise: the caption mutation slipped through the first draft (its telemetry check scanned only the SVG; widened to the caption and legend and re-proved), and removing the module's own reduced-motion guard is invisible in a browser because the platform's global reduced-motion rule also stops it, so `test_reduced_motion_guard_lives_in_the_module_itself` pins it statically. Found by looking at the render, not by a check: the first layout ran node 07's label "BLOCKCHAIN / NFT" into node 14; fixed by offsetting the outer ring (-75 deg), and the overlap geometry check now exists so it cannot return silently.

**Not done / not verified.** (1) It is an illustration: nothing in it is measured. The rings and spokes are composition -- they imply no hierarchy, region, server, traffic or dependency, and the owner's "geopolitical backend" wording has no counterpart in this repo (recorded in `OMEGA_TAXONOMY.md` §9). (2) On a phone the numbered nodes are small (about 9 px); the legend is the reading and tapping surface, by design. (3) Not wired into the dimension shift or the council; not added to world.html, where live status lives, so the two are never confused. (4) Checked in software-rendered Chromium only; no real-device look. (5) Not deployed.
