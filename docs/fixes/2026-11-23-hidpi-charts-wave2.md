### hi-DPI charts, wave 2: twelve static-chart pages, and a growth loop the first helper would have shipped (2026-11-23)

**Why.** The owner asked to extend the hi-DPI fix (PR #1545, money cluster) to the other canvas files. Audit on `origin/main` at `4df11d664`: **70** files call `getContext('2d')` without mentioning `devicePixelRatio` (a `grep` over `*.html` and `*.js`; the earlier session figure of 72 of 91 came from a different count and is not comparable). They fall into groups that need different treatment, so this is **not** "all 70":
- **Done (this entry): 12 static-chart pages, 19 canvases** — `journal` (2), `mood` (2), `reading`, `time`, `water`, `weekly`, `workout`, `ops` (2 sparklines plus the latency chart, 3 canvases), `physiology` (4: three through `drawTrend`, one blood-pressure), `fasting`, `contacts`, `cipher`. Each page now loads `omega-canvas-hidpi.js` (end of `<head>`) and sizes through `OmegaCanvas.fit` / `fitWidth`; drawing code reads `OmegaCanvas.size(c)` for W and H.
- **Deliberately not done:** full-viewport animated backgrounds (404, enter, honors, offline, pending, account, media, profile, `omega-confetti.js`: a 3x store is 9x the pixels repainted every frame for a particle layer nobody inspects); pixel-exact outputs (`omega-qr.js`, `omega-share-card.js`: their pixel size is the content); already hand-doubled (city, cosmos, family, media, `omega-page-emblem.js`, vault, subscriptions); interactive canvases that hit-test with `getBoundingClientRect` (agent-network, architect, atlas, dashboard, ecosystem, knowledge, network, nexus, mindmap, queue) because a store larger than the CSS box silently breaks their pointer maths and each needs its own change; and the small ambient rings/glyphs on `analytics`, `body`, `nutrition`, `sleep`, `stoic`, `houses`, `ascension`, `points`, `sigil`, `identity`, `beacon`, `breath`, `clarity`, `automation`, `triads`, `trophies`, `social`, `interface-omni`, which are animated loops of tens of pixels.

**Fix.** `omega-canvas-hidpi.js` gained `fitWidth` (the `c.width = c.offsetWidth || N` shape; remembers the logical height because after `fit()` the attribute holds the larger store height), `size()` (CSS-pixel size of the last fit), and an **automatic pin**: if changing the store changes the canvas's laid-out width, or the canvas is not displayed and its CSS width is `auto`, `fit()` sets an explicit CSS size. Without it a canvas with no CSS width is laid out at its own store size: `mood.html`'s `freq-canvas` went 300, 600, 824 px across 1x/2x/3x. The first version of this wave relied on the per-site `{size:true}` flag the pilot used; the harness showed that is one site to forget per page, so the detection is in `fit()` and the flag stays only as an override.

**Verified.** `scripts/verify-hidpi-charts.js` now covers **27** charts (9 pilot + 18 here) at 1x/2x/3x, **150/150**. `physiology#c-weight` is the one changed canvas not exercised on its own: it goes through the same `drawTrend` as `c-rhr` and `c-hrv`, but its data comes from a different store and was not seeded; against pristine `origin/main` the same harness gives **96/108** at the point the first wave-2 batch was added (every one of the 11 charts then covered fails the store check, plus `ops#live-spark`'s painted-region check), the fixed tree 108/108, then 150/150 once the remaining 7 charts were added. Checks added for wave 2: after the chart is drawn again and the window resized, its CSS size is unchanged (the growth-loop check); painted coverage non-blank at every scale with a per-chart minimum; charts are redrawn from known data through the page's own draw function (journal and cipher, which are module-scope, through their own UI: a real passphrase set up and a real saved entry). Stress: **3 of 3 parallel runs 150/150** (an earlier parallel run had 2 of 3 clean; see below). Mutation-tested: no `setTransform` fails 21 checks; auto-pin disabled fails `mood#freq-canvas`'s two layout checks and `ops#live-spark`, and still fails after the retry (so the retry does not hide a deterministic bug); a page reading `c.width` back instead of `OmegaCanvas.size` fails `test_wave2_drawing_code_reads_css_size_not_the_backing_store`. Seen, not just counted: before/after crops of `expenses.html`'s chart axis text at 3x in the PR for the money cluster; none taken for the 19 wave-2 canvases.

**Found along the way.** (1) My first mood edit matched only one of its two functions (`drawFreq` has a line between the width and the W/H reads) and left it unchanged; found by checking for remaining `c.width =` assignments, then fixed. (2) The harness's journal entry was blank because an empty journal draws its bars at 7 percent alpha; the harness now saves a real entry. (3) Intermittent layout state on **pristine `origin/main`**, not caused by this change: `physiology.html`'s content column is 868 px wide instead of 539 in about 1 of 32 loads under load (and `contacts.html` 868 vs 504 on the fixed build, 1 of 32), stable within a load, cause not identified. The harness re-measures a cross-scale mismatch once; the retry fired in 2 of the 3 parallel stress runs (both times on physiology).

**Not done / not verified.** (1) The unlisted ~50 files above. (2) Software Chromium only; no real retina or phone. (3) The late-flip layout state is unexplained. (4) `fasting` and `contacts` charts are verified from seeded data through their draw functions, not through their add/save UI. (5) Memory: wave 2 adds 19 stores at up to 9x the pixels; the largest is 824x140 CSS, so about 1 MB per canvas at 3x, not measured as a performance cost. (6) Not deployed.
